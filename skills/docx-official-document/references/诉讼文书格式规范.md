# 诉讼文书格式规范（v1.0）

> 来源：对多份实际归档的诉讼文书 OOXML（`styles.xml` / `document.xml` / `footer*.xml`）逐项解析后整理。
>
> **适用范围**：答辩状（民事答辩状）、起诉状、证据清单、质证意见，以及同类诉讼文书。
> **适用场景**：需要与既有文书格式保持完全一致（同一法院、同一团队的持续性文书）时使用。
> 与「公文格式规范」的区别：诉讼文书采用**标题 1–4 的固有层级 + 案号居右 + 落款居右 + 法院名顶格**，不套用培训/课程类文档的排版。

## 1. 页面与页脚

| 项目 | 值（twips） |
|---|---|
| 纸张 | A4，11906 × 16838 |
| 页边距 | 上/下 1440（2.54cm）、**左/右 1800（3.175cm）** |
| 页眉/页脚距 | header 851、footer 992 |
| 页脚 | **居中 PAGE 域**（域代码 `PAGE   \* MERGEFORMAT`），≥2 页必须有 |
| 页眉 | 无内容 |

## 2. 文档默认（docDefaults）

```xml
<w:pPrDefault><w:pPr>
  <w:spacing w:line="440" w:lineRule="exact"/>            <!-- 固定行距 22 磅 -->
  <w:ind w:firstLineChars="200" w:firstLine="200"/>       <!-- 首行缩进 2 字符 -->
</w:pPr></w:pPrDefault>
```

## 3. 样式定义（核心 · 与样本逐项一致）

| 样式 | 中文字体(eastAsia) | 西文(ascii/hAnsi) | 字号 | 加粗 | 对齐 | 缩进 | 间距 | 大纲级别 |
|---|---|---|---|---|---|---|---|---|
| **Normal（正文）** | 仿宋_GB2312 | Times New Roman | 15pt（sz 30） | 否 | 两端对齐 | 首行 2 字符 | — | — |
| **标题 1**（文书名，如「民事答辩状」） | 方正小标宋简体 | Times New Roman | 22pt（sz 44） | 是 | **居中** | 首行 0 | 段后 1 行 | 0 |
| **标题 2**（答辩人/被答辩人/答辩请求/事实与理由/一、） | 黑体 | Times New Roman | 15pt（继承） | 是 | 左 | 首行 2 字符 | **段前 156 / 段后 156** | 1 |
| **标题 3**（一、二、…） | 楷体 | Times New Roman | 15pt（继承） | 是 | 左 | 首行 2 字符 | 继承 | 2 |
| **标题 4**（（一）/1. 2.） | 仿宋_GB2312 | Times New Roman | 15pt（继承） | 是 | 左 | 首行 2 字符 | 继承 | 3 |
| **标题 5**（质证意见三层，可选） | 仿宋_GB2312 | Times New Roman | 14pt（sz 28） | 是 | 左 | 首行 2 字符 | 继承 | 4 |

要点：
- `标题 2/3/4` 的 **eastAsia 分别为 黑体 / 楷体 / 仿宋_GB2312**；均 `keepNext`。
- **标题 2/3/4 都必须保留首行缩进 2 字符（600 twips），绝不能顶格。**
- 层级编号（一、/（一）/1.）**手打**，不用自动编号。
- 样式必须用 Word **内置** `heading 1`–`heading 4`（自带 outlineLvl），保证导航窗格与 TOC 可用。
- 例外说明：早期样本的标题 1 曾为「宋体 18pt」，属旧写法；**以「方正小标宋简体 22pt」为准**。

1. 标题「证据清单」→ 标题 1（居中）
2. 案号 → 正文，**右对齐**

5. 空行
6. **三列表格**（样式 `Table Grid`）：
   - 表宽 8505 dxa；列宽 **序号 851 / 证据名称 1706 / 证明内容 5948**
   - 表头行：`序号 | 证据名称 | 证明内容`，**居中**
   - 数据行：序号列**居中**；证据名称、证明内容列**两端对齐**
   - 单元格内文字：首行缩进 0、固定行距 22 磅、**字号随正文（仿宋_GB2312 15pt）**——注：培训/课程类文档的「表格内小四 12pt」不适用于诉讼文书表格
   - 边框：单线 0.5 磅（sz=4）

## 7. 命名与存放

- 文件名：`{文书类型}【相对方】项目简称案号.docx`，如 `民事答辩【×××】××项目B（2026）粤XXXX民初XXXX号.docx`、`质证意见【×××】××项目A(2026)粤XXXX民初XXXX号.docx`。
- 存放：答辩状/质证意见/证据清单归该案的材料子夹（若案卷为扁平结构则直接存案件夹）。

## 8. 实现陷阱（实测踩坑，务必遵守）

用 python-docx / docx-js 依本规范生成文档时，**必须**处理以下两点，否则字体与字形会走样：

1. **必须删除样式里残留的 `*Theme` 字体属性**。
   Word 内置 `Heading 1`~`Heading 4` 样式的 `w:rFonts` 默认带
   `asciiTheme="majorHAnsi" eastAsiaTheme="majorEastAsia" hAnsiTheme="majorHAnsi" cstheme="majorBidi"`。
   仅 `set()` 上 `w:eastAsia` 而**不删 theme 属性**时，Word/WPS 会优先按 theme 解析
   （theme1.xml 的 `majorFont`/`minorFont` 的 `ea` 为空 → 回退到 **MS Gothic** 或 **宋体**），
   表现为「Office 里显示 MS Gothic、内置阅读器显示宋体」，与要求的仿宋_GB2312/黑体/楷体/方正小标宋简体全不符。
   → 生成后必须 `for k in list(rf.attrib): if k.endswith('Theme'): del rf.attrib[k]`，并逐样式复核。
   （`docDefaults` 的 `rPrDefault/rFonts` 可保留 theme 属性，与样本一致；但 `Normal` 与 `Heading 1-4` 必须只有显式字体。）

2. **Word 内置 `Heading 4`（以及部分内置标题样式）自带 `w:i`（斜体）**。
   只设 `w:b` 不关斜体，标题4 会渲染成**加粗斜体**。
   → 对 `Normal` 与 `Heading 1-4` 一律显式写 `<w:i w:val="0"/>` 与 `<w:iCs w:val="0"/>`。

3. **缩进要写在段落上，不能只靠 docDefaults**。
   样本的正文段都带直接 `w:ind w:firstLine="600"`、标题段带 `w:firstLine="602"`、受文法院行带 `w:firstLine="0"`；
   若只依赖 docDefaults 的 `firstLineChars=200/firstLine=200`，不同渲染器取值不一致（可能只缩进 0.35cm）。
   → 每段都显式写 `w:ind`。

4. **「此致」空 2 格、「××人民法院」顶格**：`此致` 段落 `firstLine="600"`；法院名段落 `firstLine="0" firstLineChars="0"`。

5. **标题不要写「【程序抗辩】」「【实体抗辩】」等标签**（约定）。要区分抗辩类型时，用 **Word 批注**（`doc_insert_comment`，点锚即可）在对应标题上标注，保持标题文字干净。

6. **python-docx 模板 `docDefaults` 里 `pPrDefault` 已自带一个 `w:pPr`**（spacing 276 auto）。
   追加行距/缩进时必须**复用该 pPr**（清空子元素后写入 spacing/ind），不能 append 第二个 `w:pPr`，否则 XSD 报 "pPr not expected"。
   同理 `pPrDefault` 若不存在，须插在 `w:rPrDefault` 之后（`rPrDefault.addnext()`），不能直接 append 到 docDefaults 末尾。

7. **段落级 `w:ind` 必须插在 `w:jc` 之前**（pPr 子元素顺序：… spacing → ind → jc …）。
   用 python-docx 先设 alignment 再手工 append ind 会把 ind 排到 jc 后面，XSD 报 "ind not expected"。
   → `jc = ppr.find(qn('w:jc')); jc.addprevious(ind) if jc is not None else ppr.append(ind)`。

8. **python-docx 默认模板 `word/settings.xml` 的 `<w:zoom w:val="bestFit"/>` 缺 `w:percent`**，XSD 会报错。
   保存后对该文件做一次 zip 重写，把 `<w:zoom ` 替换为 `<w:zoom w:percent="100" `。

9. **批注可直接用 python-docx 1.2.0 原生 API 一次成型**（无需 editor_sdk/comment.py 两步）：
   `doc.add_comment(runs=run, text="…", author="reviewer", initials="FA")`——runs 传段落内的锚点 run 即可，
   自动生成 comments.xml/commentsExtended.xml 等全部关联部件并落位锚点，比 SDK 通道稳定（无 `document is not open` 掉线问题）。

## 9. 颜色与批注

### 9.1 全文只用黑色

- **所有文字一律黑色**（`w:color w:val="000000"`），标题、表格、批注文字均不得使用主题色或任何彩色。
- 生成时须同时处理 **样式层** 与 **run 层**：`Normal` 与 `Heading 1–4` 的 `w:rPr` 内写 `<w:color w:val="000000"/>`，并**删除 `themeColor` 等主题色属性**；每次 `add_run` 后同样写黑色，避免继承 Word 内置标题样式的蓝色（2F5496）。

### 9.2 批注用法（作者统一写 `reviewer`）

约定：**批注不限于标题，应尽量多写；正文从简、细节入批注**。批注内容建议覆盖：

| 位置 | 批注内容 |
|---|---|
| 一级标题（一、二、…） | 标明该段属**程序抗辩**还是**实体抗辩**（**禁止写进标题文字**，标题必须干净） |
| 每条法条／司法解释／判例引注处 | `【引注核验 #N】`＋**法条原文**＋核验来源＋结论，**N 与《引注核验表》行号一致**；判例写案名＋法院＋案号＋文书类型＋裁判要旨 |
| 答辩请求／事实与理由 | **庭审答辩要点**：抗辩顺序、举证责任分配、对方可能的反驳与应对 |
| 事实与理由 | **待收集／待补证据清单**（逐项写明证明目的） |
| 此致／落款处 | **提交提示**：副本份数、期限、开庭时间核实、是否需补充答辩／质证意见 |
| 其他 | 法律规定原由、风险提示、需向承办律师确认的事项 |

- 插入方式：`doc_insert_comment`（`range_begin == range_end` 为点锚），锚定在该内容首次出现的文本处；`author="reviewer"`。
- 与引注核验流程配套使用，序号与《引注核验表》一一对应。
