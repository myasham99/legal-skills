# 案件文件命名与归档（naming-n-filing）

本技能封装了 `naming_n_filing.py` 脚本——一套用于**××××公司公司法务案件材料**自动识别、规范命名与归档的完整工具。

它的职责：接收一个案件材料文件（PDF / 扫描件 / txt），通过 OCR 自动提取**案号、相对方、项目名称**，按照既定命名规范生成标准文件名，然后在 D 盘案件中搜索匹配的既有文件夹并完成归档；对起诉材料，还可指派律师并归档到 Z 盘待指派目录。

## 何时使用

- 用户给出一个案件材料文件路径，要求"处理 / 命名 / 归档 / 归类 / 整理"。
- 用户提到起诉状、答辩状、判决书、裁定书、传票、证据、保全、执行等材料名称。
- 用户要求"把这份材料放到对应案件文件夹里""查一下这个案件在哪个目录""指派律师"。
- **新收到起诉材料**：从起诉材料包（传票+起诉状+证据）提取字段 → ①登记《公司被诉案件收文台账》 ②归档到 Z 盘 02待指派律师的案件。**每次识别出"新收起诉材料"都应主动询问用户是否需要一并完成这两步**（详见下节）。
- 需要从一份法律文书里提取案号、相对方、项目、开庭日期等信息。

## 新收起诉材料 · 两件事（台账 + Z盘待指派）

识别出某份材料是**新收到的对方起诉材料**（含"诉"字起诉状/传票/参加诉讼通知书，我方为被告/被申请人/第三人）时，主动向用户确认是否需要**一并完成**：

1. **填写收文台账字段**——参照桌面《公司被诉案件收文台账.xlsx》（同款模板可能经邮件/共享盘下发，先找到最新版）的输出字段与规则，字段列映射见 `references/ledger_fields.md`。**注意 O 列案件状态**：新收案件统一填 `一审中`，仅当材料明确为中级人民法院+民终案号才填 `二审中`（用户 2026-09-07 约定）。
2. **归档 Z 盘待指派律师目录**——复制起诉材料到 `Z:/5 案件管理/0案件收文2026年/02待指派律师的案件/{MM.DD}开庭-{分公司}-{相对方简称}-{案号}-{标的额}万元/`，案件文件夹命名逻辑见 `references/directory_routing.md` 第 3 节。

先做 D 盘收档（命名归档）→ 再提取台账字段 → 最后 Z 盘指派，或按用户习惯顺序执行。不要自行替用户决定是否委托/归档，先问。

## 收文处理 · 必须提醒事项（用户 2026-09-09 强制约定）

处理**任何**新收起诉材料/传票/判决时，输出台账或汇报前必须检查以下两项并**醒目提醒**用户。

> **提醒形式限制（用户补充澄清）**：提醒**仅限对话框回复中的加粗黑字文字标注**；**不得**写入/修改文件或文件夹命名，**不得**创建自动化/定时提醒任务。

1. **急案提醒（开庭 10 日内）**：开庭日期距当前日期 **≤10 日**（含当日）即算急案（参考案：翠亨法庭 9.4 出传票 → 9.8 送达 → 9.10 开庭），汇报时注明「**⚠️ 急案：距开庭仅 X 天**」，并提示尽快委托/准备。
2. **××股份授权提醒**：材料中当事人（尤其被告/第三人）含 **××××股份有限公司** 时，汇报时注明「**⚠️ 需办理××股份授权**」，提示用户走股份授权流程（参考案：0908【广日电梯】中山翠亨（20XX）Xxxxx民初XXXX号，被告二=××股份）。


## 环境依赖

脚本依赖以下 Python 库（见同目录 `requirements.txt`）：

- `pypdf`：PDF 文字层提取
- `PyMuPDF`（`import fitz`）：PDF 渲染 / 备用文字层提取 / OCR 预处理
- `Pillow` + `imagehash`：重复页检测（感知哈希）
- `Tesseract OCR`：外部程序，扫描件 OCR 识别（需 `chi_sim` 中文语言包）

安装：

```bash
pip install -r requirements.txt
# Tesseract 需单独安装，并在脚本顶部 TESSERACT_PATH 中配置路径
```

```bash

```

启动后输入待处理文件的完整路径（输入 `q` 退出），脚本会引导用户逐步完成识别、确认、搜索、命名与归档。

## 核心工作流程

脚本的 `process_file()` 走完以下六步：

1. **OCR 提取**：按优先级取文本 —— 同名 `.txt` → `.txt` 直接读 → `pypdf` 文字层 → `fitz` 文字层 → `Tesseract` 自动 OCR → 手动粘贴。
2. **信息提取**：提取案号（`extract_all_case_numbers`）、相对方（`extract_counterparty`，自动排除己方关键词）、项目简称（`extract_project_short_name`）。
3. **确认修正**：交互确认相对方、补充项目名。
4. **判断材料类型**：按 `MATERIAL_PREFIXES` 简称库匹配材料前缀（如"一审判决""开庭传票""保全申请"），并判断是否二审。
5. **多维度搜索回填**：用案号、编号、相对方、项目等多维关键词在 D 盘搜索既有案件文件夹，由用户选择回填或新建。
6. **生成文件名并归档**：按 `{前缀}【{相对方}】{项目}{案号}` 生成文件名，路由移动到对应目录；判决裁定类双写；起诉材料可选指派 Z 盘。

## 命名规范（速览）

文件名格式：

```
{材料类型}【{相对方}】{项目}{案号}{后缀}
```

- 材料类型取自 `MATERIAL_PREFIXES`（如"起诉材料""一审判决""开庭传票""保全申请"）。
- ★ **前缀用字：尽量 4 个字**（用户 2026-09-14 约定）。材料名较长时压缩成 4 字简称，例：「诉讼支付金额明细表」→ `诉讼明细`；已有 4 字前缀（起诉材料、一审判决、二审判决、质证意见、债务计算、诉讼明细…）沿用。**压缩后语义要能独立看懂**，不要为凑 4 字而含糊。
- ★ **拿不准时给方案让用户选**：前缀无法确定、或有多个都说得通的写法时，**列出 2–4 个候选前缀**（附一句含义说明）请用户挑，不擅自定名；确定后的新前缀要同步写回 `MATERIAL_PREFIXES` 与本文件。
- 相对方是对方当事人简称（已去除"有限公司""集团"等后缀，排除己方）。
- 项目是项目简称（如"星光海岸""万江保利"），无法关联时用"未知项目"。
- 案号做了清洗：去空格、括号转全角、剔除 OCR 噪声（如 `#` `$` 等误读字符）。
- 仅「一审判决」在归档到【判决裁定】目录时，文件名前额外加收到日期前缀 `(YYYYMMDD收)`（**半角括号**）；二审判决、调解书、裁定不加。
- 二审材料若含一审案号，文件名回填一审案号。
- **管辖法院尾缀**：已知管辖法院、但法院尚未分配具体案号时（如刚提交起诉状、尚未受理），在命名**末尾**补充 `(年份)粤XXXX民初` 尾缀（不含序列号/号），例如 `起诉材料【×××】鄱阳B（20XX）粤XXXX民初`。法院代码查 `references/court-codes.md`（粤+地级市2位+基层法院2位）；可用 `suggest_court_code(project=...)` 按项目/地点关键词辅助推定（仅供参考，以受理通知书为准）。`generate_new_filename(..., court_code="0114")` 会自动追加该尾缀。

详见 `references/naming_spec.md`、`references/court-codes.md`。

## 扫描件处理要点（2026-09-14 实战沉淀）

- **本 skill 目录名含连字符**（`...\skills\naming-n-filing`），模块文件仍是 `naming_n_filing.py`。以脚本方式调用时 `sys.path.insert(0, r"…/skills/naming-n-filing")`，**不要**再用下划线目录名（会 `ModuleNotFoundError`）。
- **方向校正**：若 PDF `page.rotation != 0`（如 270），fitz 默认渲染出的图仍不是正向；须对渲染图再旋转（本例 `PIL.Image.rotate(-90, expand=True)`）后才能 OCR / 目视。用「CJK 字符数最多」自动选向**不可靠**（本例 180° 乱码反而计数最高），以 `page.rotation` 为准并目视确认。
- **表格类扫描件不要只信 OCR**：`--psm 6` 会把表格行读散。应 260–330dpi 灰度渲染 + 旋转校正后**目视核读**（Read 图片），OCR 仅作定位辅助。
- **一包多案要拆分**：同一扫描批次含多个案号时（如 `诉讼支付金额明细表 / 债务计算表` 双案合订），按案号用 `fitz.insert_pdf(from_page,to_page)` 拆成独立 PDF，再分别入对应案夹（付款/履行类 → `【执行履行】\债务计算\债务计算【相对方】项目（一审案号）\`）。
- 扫描件临时目录：`C:\Users\ACME\AppData\Local\Temp\wb_naming\`（脚本、渲染 PNG、OCR 文本可留存复用）。

## 混合包分类归档（2026-09-17 实战沉淀）

一个扫描 PDF 里混装**不同去向**的材料（如「1 张授权委托书 + 14 张签到表」）时的处理：

1. **逐页识别去向**：渲染全部页（rotation 校正）→ 目视读每页标题/表头，给每页打去向标签。
2. **按去向分组拆分**：用 `fitz.insert_pdf(from_page=..., to_page=...)` 单页拆出独立 PDF，分别投递到各自目标目录。
3. **授权委托书**：归入**对应案件夹**（`【被诉案件】YYYY年M月收/{MMDD【相对方】项目案号}/`），前缀沿用该案既有写法（本案既有 `授权材料【…】…`，故用 `授权材料`）。**注意**：加签名/盖章的重扫件通常是**更新版**，同名并存前先看是否已有同名前缀文件 → 按 2026-09-14 约定默认**覆盖旧版**（只留最新签字版），但**先比对差异并问用户**更稳妥。
4. **党支部签到表**：归档 `D:\【×××】\【普通】\党支部会议\法务部签到表`，命名 `{序号}-法务部签到表-{级别}{组内序号}`，例 `01-法务部签到表-全体1.pdf`。
   - **级别靠名单人数判定，不靠标题**：这些签到表标题一律是通用的「××××有限公司签到表」，**没有**印"全体/党员/支委"字样，只能按**花名册人数逐级递减**推断：人数最多=全体、居中=党员、最少=支委。
   - 判定依据看**印刷体姓名栏的行数**（不是签名数；很多行有字但未签）。**双栏表**要左右两栏都数（本例全体表为 10+10=20 人）。
   - `{序号}` 由大到小：全体=01、党员=02、支委=03；同级多张再加组内序号 `1/2/3…`。
   - 序号与级别的对应关系**每次先问用户**（本次确认：## = 序号，非月份）。
