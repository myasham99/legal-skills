# 目录结构与归档路由（directory_routing）

本文档是 `naming_n_filing.py` 中目录结构、搜索匹配与归档路由规则的详细展开。

## 1. 核心路径常量

| 常量 | 路径 |
| --- | --- |
| `D_ROOT` | `D:/【用户名】` |
| `D_LITIGATION` | `D:/【用户名】/【诉讼】` |
| `D_DEFENDANT` | `D:/【用户名】/【诉讼】/【被诉案件】` |
| `D_JUDGMENT` | `D:/【用户名】/【诉讼】/【判决裁定】` |
| `D_PRESERVATION` | `D:/【用户名】/【诉讼】/【财产保全】` |
| `D_EXECUTION` | `D:/【用户名】/【诉讼】/【执行履行】` |
| `D_PLAINTIFF` | `D:/【用户名】/【诉讼】/起诉案件` |
| `Z_ROOT` | `Z:/5 案件管理/0案件收文2026年/02待指派律师的案件` |
| `Z_BRANCH` | `中山` |

## 2. D 盘目录树

```
D:/【用户名】
└── 【诉讼】
    ├── 【被诉案件】          被诉案件主归档区
    │   └── {MMDD}【{相对方}】{案号}   ← 找不到既有文件夹时新建
    ├── 【判决裁定】          判决/裁定按月归档
    │   └── 【判决裁定】YYYY年M月收
    ├── 【财产保全】          保全材料
    │   └── 解封申请         解封类单独子目录
    ├── 【执行履行】          执行类材料
    └── 起诉案件             起诉类材料
```

## 3. Z 盘指派目录

### 3.1 待指派目录（AI 负责归档新收起诉材料）

新收到的起诉材料（我方为被告/被申请人/第三人，尚未委托律师）归档到 Z 盘**待指派目录**：

```
Z:/5 案件管理/0案件收文2026年/02待指派律师的案件
└── {MM.DD}开庭-{分公司}-{相对方简称}-{案号}-{标的额}万元
    └── {材料文件}.pdf / .docx
```

**案件文件夹命名格式（2026-09 实测确认）：**

```
{MM.DD}开庭-{分公司}-{相对方简称}-{（年份）粤XXXX…号}-{标的额}万元
```

| 段 | 说明 | 示例 |
| --- | --- | --- |
| 开庭日期 | `MM.DD` 两位月日；未排期用 `待排期`/`待排庭` | `10.12开庭` |
| 分公司 | 分公司简称：中山 / 广分 / 总包 / 深圳 等（非"××分公司"全称） | `中山` |
| 相对方简称 | 对方当事人简称（同 D 盘命名简化规则，剔除"有限公司"等） | `岐恩建筑` |
| 案号 | 全角括号完整案号 | `（20XX）粤XXXX预鉴XXXX号` |
| 标的额 | 诉讼请求合计（万元），保留 2 位小数 | `84.59万元` |

实测样例：
- `10.12开庭-中山-岐恩建筑-（20XX）粤XXXX预鉴XXXX号-84.59万元`（新建）
- `11.16开庭-广分-樊俊富-（20XX）Xxxxx民初XXXX号-40.53万元`（2026-08-31 已建）

文件入夹时用 D 盘规范的 `{材料类型}【相对方】{项目}{案号}{后缀}` 文件名（如 `起诉材料【岐恩建筑】明阳二三（20XX）粤XXXX预鉴XXXX号.pdf`）。此目录下**未开庭前**起诉材料原件应 copy 而非 move（D 盘被诉目录仍保留原件）。

> 旧格式 `{开庭日期}开庭-中山-{相对方}-{案号}` 已废弃（缺少分公司简写与标的额），仅早期文件夹残留。

### 3.2 已委托目录（专人跟进，AI 不处理）

```
Z:/5 案件管理/0案件收文2026年/02待指派律师的案件/00已委托案件/
├── 01黄律/
├── 02崔律/
├── 03许律/
└── 04云贵川/
    └── {开庭}开庭-{分公司}-{相对方}-{案号}
```

- 由**专人征询律师确认委托后自行归档**，AI 不需要也不能代为处理。
- 各律师子目录内案件文件夹命名同 3.1 逻辑（存在少量历史变体，如 `8.31开庭-中山-江门市双广建筑装饰工程有限公司（20XX）粤XXXX民初` 无标的额、`0923开庭-总包-奉继春-1.4万-（20XX）Xxxxx民初XXXX号` 标的额在前），以较新条目 `11.11开庭-中山-南山人防-（20XX）Xxxxx民初XXXX号` 与 3.1 格式为准。
- 含 `00黄律待确认` / `00崔律待确认` 等子目录：律师已口头确认、材料待补，AI 不处理。
- **学习/核对用途**：需要确定某案归哪位律师时，可读取这些子目录列表反查。

## 4. 搜索匹配引擎

### 关键词维度（`_build_search_keywords`）

| 维度 | 关键词来源 | 打分权重 |
| --- | --- | --- |
| 完整案号 | 提取的案号（清洗后） | +100 |
| 案号编号片段 | 案号中最后一个 ≥3 位数字段（核心编号） | +50 |
| 相对方 | 相对方全称（清洗后） | +80 |
| 相对方简称 | 相对方前 4 字（长度 >4 时） | +30 |
| 项目名 | 项目简称 | +40 |
| OCR 额外案号 | 正文中提取的其他案号 | +60 |

所有关键词统一经 `_clean_for_search` 清洗（去括号、空格、OCR 噪声）后再比对。

### 搜索范围（`search_case_folders`）

1. 默认在 `[D_DEFENDANT, D_PRESERVATION, D_EXECUTION, D_PLAINTIFF, D_JUDGMENT]` 递归搜索。
2. 未命中时，扩大到整个 `D_ROOT` 递归搜索。
3. `rglob("*")` 遍历文件夹与文件（`dirs_only=True` 时只搜文件夹），按分数降序返回。

### 结果展示与回填

- `★★★`（≥100）、`★★`（≥50）、`★`（其余）。
- 用户选择后，若选中的是文件则取其父文件夹名，用 `extract_info_from_folder_name` 反向解析相对方/项目/案号并回填。

## 5. 归档路由规则（route_and_move）

### 目标目录判定

1. **保全 / 解封**：`解封申请` → `D_PRESERVATION/解封申请`；其余含"保全" → `D_PRESERVATION`。
2. **执行**（且非"执行异议"）→ `D_EXECUTION`。
3. **判决裁定**（`一审判决/二审判决/调解书/裁定`）：
   - 写入 `D_JUDGMENT/{【判决裁定】YYYY年M月收}`；
   - 同时若原案件文件夹不在 `D_DEFENDANT` 下，则额外定位/写入被诉案件目录（双路径）。
4. **起诉材料**：可选指派律师并复制到 Z 盘（见上）。

### 既有文件夹匹配 vs 新建

- 若 `process_file` 阶段已选定文件夹（`pre_selected_dir`），直接复用。
- 否则在诉讼子目录下重搜文件夹：命中则让用户选择；选择后回填案号/项目并**重新生成文件名**。
- 未命中或选择"新建"→ 在 `D_DEFENDANT` 下创建 `{MMDD}【{相对方}】{案号}`。

### 移动与复制

- 第一个目标目录：`shutil.move`（移动原文件）。
- 其余目标目录：`shutil.copy2`（复制）。
- 仅「一审判决」在判决裁定目录下文件名加 `(YYYYMMDD收)` 前缀（**半角括号**）；二审判决、调解书、裁定不加。
- 目标文件已存在时交互确认是否覆盖。

## 6. 路由决策速查表

| 材料前缀 | 归档目录 | 备注 |
| --- | --- | --- |
| 保全申请 / 保全通知 / 冻结证明 | `【财产保全】` | |
| 解封申请 | `【财产保全】/解封申请` | |
| 执行申请 / 执行裁定 / 终本裁定 / 执行款 / 债务计算 | `【执行履行】` | |
| 执行异议 | 走通用匹配 | "执行异议"不落入执行目录 |
| 一审判决 / 二审判决 / 调解书 / 裁定 | `【判决裁定】/...年月收` + 被诉案件 | 双路径 |
| 起诉材料 | 被诉案件 + 可选 Z 盘 | Z 盘需确认 |
| 其他 | 按搜索匹配或新建到被诉案件 | |
