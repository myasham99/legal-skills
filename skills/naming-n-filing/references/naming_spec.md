# 命名规范说明（naming_spec）

本文档是 `naming_n_filing.py` 中命名与信息提取规则的详细展开，供需要精确理解或调整命名规则时查阅。

## 1. 文件名格式

```
{材料类型}【{相对方}】{项目}{案号}{后缀}
```

生成逻辑见脚本 `generate_new_filename()`：

- 材料类型（`prefix`）：来自 `MATERIAL_PREFIXES` 简称库匹配。
- 相对方（`counterparty`）：对方当事人简称。
- 项目（`project`）：项目简称，缺省时用 `未知项目`。
- 案号（`case_num`）：清洗后的完整案号；二审材料若识别到一审案号则回填一审案号。
- 文件名中的非法字符 `\ / * ? : " < > |` 会被剔除。

仅「一审判决」在归档到 `【判决裁定】` 目录时，文件名前额外加收到日期前缀（**半角括号**）：

```
(YYYYMMDD收){原文件名}
```

二审判决、调解书、裁定**不加**收到日期前缀。

### 裁定书的归档路径（2026-09-17 补充）
- **判决/裁定类统一走双路径**：案件夹 + `【判决裁定】\【判决裁定】YYYY年M月收\`。
- 但**解封/解除保全裁定**不走【判决裁定】，归 `【诉讼】\【财产保全】\解封文书\`，前缀用 `解封裁定`。
- 民事裁定书（司法确认调解协议，案号含 `民特`）文件名用 `民事裁定书`，随对应调解书归档。
- 例：`民事裁定书【×××】御海阳光（20XX）Xxxx民特XXX号.pdf`；`解封裁定【×××】OPPO研发（20XX）Xxxxx民初XXXX号之二.pdf`。

### 律师函归档路由
- 归 `D:\【×××】\【普通】\【普通事务】YYYY年M月\MMDD 事项【相对方】项目\`，文件 `律师函【相对方】项目.pdf`（如 `律师函【×××】钢板桩多项目.pdf`）。
- 律师函多涉及**未诉在先的催告**，通常无案号；相对方取委托人（发函方委托的当事人）。


## 1.1 管辖法院尾缀（court-codes）

已知管辖法院、但法院尚未分配具体案号时（如刚提交起诉状、尚未受理），在命名**末尾**补充法院案号尾缀：

```
{材料类型}【{相对方}】{项目}（年份）粤XXXX民初
```

- 例：`起诉材料【×××】鄱阳B（20XX）粤XXXX民初`（不含序列号与"号"，待受理后再补全）。
- 法院 4 位代码查 `references/court-codes.md`（案号规律：粤 + 地级市 2 位 + 基层法院 2 位）。
- 可用 `suggest_court_code(project="鄱阳B")` 按项目/地点关键词辅助推定（仅供参考，**以法院受理通知书案号为准**）。
- 实现：`generate_new_filename(..., court_code="0114")` 会在末尾自动追加 `court_suffix("0114")` 的结果 `(20XX)粤XXXX民初`。
- 注意：鄱阳项目存在花都(0114)与龙华(0309)两种情况，需结合具体案卷确认管辖法院。

## 2. 材料类型前缀库（MATERIAL_PREFIXES）

按文本关键词（扫描材料正文 + 文件名）匹配，输出统一前缀：

| 分类 | 触发关键词 → 输出前缀 |
| --- | --- |
| 诉讼核心 | 起诉状/起诉材料 → `起诉材料`；答辩状→`答辩状`；答辩意见→`答辩意见`；反诉状→`反诉状`；证据→`证据材料`；质证→`质证意见`；数据确认→`数据确认` |
| 裁判文书 | 二审判决书→`二审判决`；一审判决书/判决书→`一审判决`；调解书→`调解书`；裁定书→`裁定` |
| 保全 | 保全结果通知书→`保全通知`；冻结证明→`冻结证明`；保全申请→`保全申请`；解封申请/解除财产保全→`解封申请` |
| 执行 | 执行异议/执行异议申请书→`执行异议`；执行申请→`执行申请`；执行裁定→`执行裁定`；终本裁定→`终本裁定`；执行款→`执行款`；债务计算→`债务计算` |
| 程序性 | 传票/开庭传票→`开庭传票`；授权委托书→`授权委托书`；管辖异议→`管辖异议`；延期开庭→`延期开庭`；送达地址确认书→`送达地址确认书` |
| 费用 | 上诉费→`上诉费`；诉讼费→`诉讼费` |
| 其他 | 案件策划→`案件策划`；刑事侦查→`刑事侦查`；和解协议/调解协议→`和解协议`；鉴定报告→`鉴定报告`；庭审笔录→`庭审笔录`；代理词→`代理词` |

未命中任何关键词时，默认前缀为 `其他材料`。

> **二审判决自动纠正**：当匹配结果前缀为 `一审判决`、且判定为二审（案号含"民终"/"终"，或正文含"二审"）时，自动纠正为 `二审判决`，确保判决书区分一审/二审。

### 2.1 前缀用字规则（★ 尽量 4 字，用户 2026-09-14 约定）

1. **优先 4 个汉字**：材料名较长时压缩为 4 字简称，语义需能独立看懂、不因凑字而含糊。已有 4 字前缀（`起诉材料` `一审判决` `二审判决` `质证意见` `债务计算` `开庭传票` `诉讼明细` …）继续沿用。
2. **长名 → 4 字压缩示例**：

   | 材料全称 | 采用前缀 |
   | --- | --- |
   | 诉讼支付金额明细表 / 支付金额明细 | `诉讼明细` |
   | 债务计算表 | `债务计算` |
   | 诉讼文书送达地址确认书 | `送达地址确认书`（既有惯例，超 4 字保留） |
   | 律师函 | `律师函`（既有惯例；事项类可加括号定性，如 `律师函(质保金)【…】…`） |
   | 民事裁定书（解封/解除保全） | `解封裁定`（归 `【财产保全】\解封文书\`；区别于执行裁定） |

3. **拿不准时给候选方案**：前缀无法确定、或存在多个都说得通的写法时，**列出 2–4 个候选前缀（各附一句含义）请用户选择**，不要擅自定名。
   - ★ **以卷内既有写法为第一优先**：同一案件/同一目录已有同类型材料时，**沿用该卷既有前缀**，不要另创（如南宝案既有 `授权材料【…】…`、解封文书目录既有 `解封裁定【…】…`、`解封申请【…】…`）。
4. 用户确认的新前缀，须同步写回：脚本 `MATERIAL_PREFIXES` → 本表 → `SKILL.md` 的「命名规范（速览）」。
5. 匹配顺序：`MATERIAL_PREFIXES` 为 dict、按插入顺序取**第一个命中键**，因此**更具体的长键必须排在前**（如 `诉讼支付金额明细表` 置于 `证据` 等通用短键之前，避免被抢占）。

## 3. 案号提取与清洗

### 提取

- `extract_all_case_numbers(text)`：先匹配 `（YYYY）……号` 形式，无则退化为 `YYYY……号` 形式，去重返回全部案号。
- `extract_first_instance_case_number(text)`：专门匹配一审案号 `（YYYY）……民初……号`，供二审材料回填一审案号用。

### 清洗（`clean_and_format_case_number`）

1. 去除半角/全角空格。
2. 半角括号 `()` 转全角 `（）`。

### 搜索前清洗（`_clean_for_search`）

额外剔除 `（）`、空格、`【】`、`《》〈〉`，并**剔除 OCR 噪声字符** `#$%^`~@&*+=|:;'`（例如 OCR 把"粤"误读为 `#` → `20XX#XXXX执XXXXX号` 也能匹配到 `20XX粤XXXX执XXXXX号`）。

## 4. 相对方提取与简化

### 提取（`extract_counterparty`）

按以下字段顺序扫描，取第一个命中且非己方的名称：

```
原告 → 上诉人 → 申请人 → 异议人 → 被申请人 → 被执行人 → 申请执行人
```

- 命中的名称若包含 `EXCLUDE_PARTIES` 中任一己方关键词则跳过。
- `EXCLUDE_PARTIES`：××××公司、公司、珠海分公司、××分公司、广州分公司、广东总承包、基础设施分公司、城市管网。

### 简化（`simplify_counterparty`）

依次剔除下列后缀：`（深圳）(深圳)（广州）(广州)（东莞）(东莞) 有限公司 有限责任公司 股份有限公司 集团`。

## 5. 项目识别（extract_project_short_name）

1. 在文本中匹配项目编码 `\b(12[12]\d{8})\b`，反查 `PROJECT_MAPPING` 得到简称。
2. 再用 `PROJECT_MAPPING` 中的全称 / 简称在文本中直接匹配。
3. `灏怡` 特殊处理：只要命中即收敛为 `灏怡`（避免同名歧义）。
4. 命中多个项目时，先套用 `MULTI_PROJECT_RULES` 统称；若涉及江门学校 ≥2 个，统一为 `江门学校`。
5. 多个项目且无统称规则 → 打印提示让用户手动确认，返回空。

## 7. 项目映射表（PROJECT_MAPPING · 完整版）

`PROJECT_MAPPING` 是脚本内置的**完整项目缩写映射表**，共 **78 条**，字段为 `code / full / short / profit_center`（项目编码 / 项目全称 / 简称 / 利润中心）。

**完整 78 条逐字转录见 [`references/project_mapping.md`](./project_mapping.md)，未做任何删减。**

要点：

- 项目识别通过 `code`（`12[12]` 开头的 10 位编码）或 `full`/`short` 文本匹配反查简称。
- 同名简称可对应多个项目/利润中心（如"澜汇云庭""保利和公馆""灏怡""华为二期""宝茵翠亭"等），脚本按 `code + short` 多条目处理。
- `灏怡` 特殊收敛：命中即统一为 `灏怡`，避免同名歧义。
- 若需增删项目，请同步修改脚本 `PROJECT_MAPPING` 常量与 `references/project_mapping.md`。

## 8. 开庭日期提取（extract_hearing_date）

匹配 `X月X日……开庭` 形式，输出 `MM.DD`（如 `08.06`），供 Z 盘指派目录命名用。

## 9. 重复页检测（deduplicate_pages）

用感知哈希（pHash，Hamming 距离阈值默认 8）检测 PDF 视觉重复页，返回 `[(保留页, [重复页...]), ...]`，用于剔除扫描件重复页。依赖 `fitz` + `Pillow` + `imagehash`。
