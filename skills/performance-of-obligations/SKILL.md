# 履约判决跟踪 Skill（SSOT：单一底稿、多源输出）

> **核心教训（2026-09-02）**：曾因不理解底稿口径，把 0902 报财务表填错 6 处（缺×××建材 Q 空白的 653.9 万、误判逾期口径）。底稿每月更新但**逻辑不变**，本 skill 记录完整规则，杜绝再错。

## 0. 核心原则（最重要，先读这段）

**单一事实来源（SSOT）= 分公司履约判决跟踪底稿**：`YYYYMM分公司履约跟踪.xlsx`（××分公司，标题「××分公司法律文书待履行情况台账」，每月一版 202608/202609/…）。

所有台账都从这一张底稿派生，**不要另造数据、不要沿用上月旧值**。派生关系：

```
            分公司履约判决跟踪底稿（SSOT，唯一真相源）
               │  核心键：案号 / 原告(分供商) / 项目简称 / 局-公司
   ┌───────────┼──────────────┬─────────────────┐
   ▼           ▼              ▼                 ▼
 专项借款表  总部履约跟踪表    对上级月度报送       报财务(生效待履约跟踪)
(未支付>0,   (同案未支付    (底稿+总部→      (局/公司×时间桶
 按案件+项目  R合计→未履行   AY/BP/AM)        →未支付金额合计)
 聚合)       金额P)
```

- **核心键**：①案号（规范化后）②原告（分供商）③项目简称（→ 项目全称/编码）④局/公司（履行主体 D 列）。
- **项目编码两套口径，都从 `公司项目编码.xlsx` 派生**（见 references/project-codes.md）：
  - 专项借款/总部履约跟踪 → 用 **12 开头旧码（code12）**（也见 references/project-mapping.md 的 78 条简称映射）。
  - 对上级报送 → 用 **600 开头新码优先，12 开头保留**。
- **列结构会变**（2026-08 版 R=未支付金额；2026-09 版 Q=未支付金额、R=支付流程节点）→ **每次先读表头确认列位置，切勿死记列字母**。

## 一、读懂底稿（最重要，一切的前提）

### 1.1 列结构（22 列，稳定；列字母可变，先核对表头）

| 列 | 表头 | 含义 |
|---|---|---|
| A | 项目 | 涉案项目简称（案件内按项目拆分多行） |
| B | 原告 | 原告/申请人名称 |
| C | 案号 | 案件号（可能跨行多案号） |
| D | 履行主体 | **局 / 公司**（区分上级名义、公司名义） |
| E | 争议解决机构名称 | 法院/仲裁机构 |
| F | 取得法律文书时间 | 日期 |
| G | 款项 | 本金/利息/诉讼费/贴息/鉴定费等 |
| H | 待履行金额 | 该行款项的**应履行金额**（文书确定金额） |
| I | 履行期限届满时间 | 到期日（**分时间桶依据**） |
| J | 是否逾期 | 逾期 / 即将逾期 / 空 |
| K | 支付方式 | 现金 / 供应链 |
| L | 支付时间 | 日期 |
| M | 支付单号 | JFK/YFK/CFK/TBZ/JFZ/FFK… |
| N | 单据金额 | 单据金额 |
| O | 已支付金额 | 已付金额 |
| P | 未提单金额 | |
| **Q** | **未支付金额** | **未付金额（统计首选）** |
| R | 支付流程节点 | 已支付/已签发/已通知/空（2026-09 版） |
| S | 回单 | |
| T | 原告联系方式 | |
| U | 执行风险 | 高/中/低 |
| V | 执行情况 | 已申请执行/未执行(分期支付)/支付完毕/威胁执行 |

> ⚠️ 2026-08 版：R=未支付金额、无 Q。2026-09 版：Q=未支付金额、R=支付流程节点。**用脚本前先 `assert` 表头**。

### 1.2 案件识别（最重要的坑）

- **新案件** = A、B、C **三列同时非空** 的行（该案件首行）。
- 后续行 A/B/C 为空，属于上一案件（合并单元格）。
- **例外 1**：A 非空但 B 空、C="/"（如 r108 金色城央）→ 也是**独立案件块**，需单独成案，**不能并入上一案件**。
- **例外 2**：同一案件内部 A 列会按项目继续填（如××建材：岭山林语→OPPO数据中心→华为南方工厂…），**A 非空不代表新案件**，必须三列同时非空才算。

### 1.3 金额取数口径（报财务/总部台账用）

**每行金额：Q（未支付金额）优先；Q 空白（未填）时用 H（待履行金额）兜底。**

```python
def get_val(ws, r, q_col, h_col):
    Q = ws.cell(row=r, column=q_col).value
    if Q is not None and str(Q).strip() != '':
        try: return float(Q)
        except: pass
    H = ws.cell(row=r, column=h_col).value
    if H is not None and str(H).strip() != '':
        try: return float(H)
        except: return 0.0
    return 0.0
```

- 为什么 Q 空白用 H？部分案件（如×××建材 18896 号）只有已到期期次填了 Q，后续期次 Q 空白但 H 有值（已签供应链、待履行），统计「生效待履约跟踪金额」时按 H 计入。
- **Q=0（明确填 0）≠ Q 空白**：已支付完毕的行 Q 明确填 0，不计入。

### 1.4 时间分桶（报财务 0902 表）

按 **I 列（履行期限届满时间）每行分桶**（不是按案件聚合取最小日）：

| 桶 | 条件（I ≤） |
|---|---|
| 截至8月 | 2026-08-31 |
| 2026.09-12 | 2026-12-31 |
| 2027.01-03 | 2027-03-31 |
| 2027.04-12 | 2027-12-31 |
| 更晚/未定 | 更晚或 I 为空 |

日期解析：Excel 序列号（`1899-12-30 + days`）或字符串 `'YYYY-MM-DD'` / `'YYYY/MM/DD'` 都要兼容。

### 1.5 局/公司名义

- D 列 = "公司" → 非上级名义；D 列 = "局" → 上级名义；D 列空白 → 继承上一案件块的 D（**按案件块传播**，合并单元格，不能按行判断）。

### 1.6 异常数据处理

- **孤立金额行**（如 r144 仅 Q=28,639,522、A-P 全空、无案件归属）→ 误填/残留，**排除不统计**。
- 鉴定费负数（如 -450）→ 按实际值参与合计（冲减）。
- 案号 "/"（待定）→ 金额照常统计，案号列保留 "/" 待补。

### 1.7 统计脚本

`scripts/lvpan_stat.py`：按「局/公司 × 时间桶」统计未支付金额（Q 优先 H 兜底），用法 `python lvpan_stat.py <底稿路径> [截止日]`，已与用户手填值验证一致。

## 二、从底稿派生各台账（一表复用）

### 2.1 专项借款表

**任务**：把底稿「未履行」记录写入同月【专项借款】表。

- **「未履行」判定**：底稿「未支付金额」列 > 0。排除：合计行（款项列 G 为空）、负数冲减（如鉴定费 -450）。
- **聚合粒度**：按「案件（原告+案号）+ 项目」聚合，同一案件同一项目的本金/利息/诉讼费合并，涉及金额 = 未支付金额之和。一个案件涉及多项目时拆多行（如××建材、×× 7351 号）。
- **列映射**（底稿 → 专项借款）：
  - 投诉平台/诉讼法院 ← 争议解决机构名称（E）
  - 投诉编号/案件号 ← 案号（C，多案号用换行保留）
  - 涉及分供商 ← 原告（B）
  - 涉及金额 ← 未支付金额合计
  - 涉及项目 ← 项目全称（A 列简称 → references/project-mapping.md 的 full）
  - 项目编号 ← **code12（12 开头旧码，不是利润中心）**
  - 借款事项 = 保案件履约跟踪（固定）
  - **I 列（项目可用资金）、J 列（项目累计借款）留空，给财务填**
  - K 列（备注）填「支付方式」（现金/供应链，混合写「现金/供应链」，来自底稿 K 列「支付方式」）。**不要填执行情况**。
- **项目简称映射差异**（底稿简称 vs 映射表 short 不同，需留意）：OPPO数据中心→OPPO数据、华为南方工厂→华为二期(1220089366)、OPPO研发中心→OPPO研发、OPPO滨海湾→OPPO滨海湾(1220160260)、明阳二三期→明阳二三、宝茵翠亭→1220101616（全称取"…住宅小区建设工程总承包项目"）、保利四期和公馆→1220130177（四期非三期）、"三一蓝海"/"三一平沙"都→1220016081。
- 项目简称 "/"（待定）→ 项目编号留空（项目列保留 "/"），需人工确认补全。
- **多项目案件的拆分逐月变动**（××建材、×× 7351 号）→ 每次以底稿 A 列实际归属为准，**不要沿用上月拆分**。
- **模板结构**：专项借款 sheet1 数据区原为行 5-38（34 行），超出的需 `insert_rows(39, N-34)`。`insert_rows` **不移动签名区合并单元格**（A47:B47 等），须「先 unmerge 旧合并 → 插行 → 写数据 → 再 merge 到 +N 位置」。小计/总计行 F 列填合计金额。
- 参考脚本：`C:\Users\ACME\.workbuddy\tmp\write_liubao.py`（openpyxl，解析+映射+写入）。

#### 专项借款多批次去重（月度复用）

- 专项借款表可能含多个 sheet（如「8月5日」「8月24日」两个批次），每 sheet 结构相同（含广州/中山/总承包分公司分块，分公司名在 A 列，数据行案号在 D 列）。
- **规则**：前一批次（如 8月5日）已申请过的借款，后一批次（如 8月24日）不得重复申请，重复的标出来。
- **判定**：按「案号」匹配。正则提取 `粤(\d+)` 法院代码 + 类型（民初/民终/民特/民再/民监/民申/民调/穗天综调/行审/仲案）+ 序号，规范化（全角括号转半角、去空格）后比对集合交集。
- **标出方式**：后一批次 sheet 中重复行**整行标黄 FFFF00** + 备注列(K)追加「重复8月5日已申请」。
- **提取分公司区间**：A 列="××分公司"开始，遇 A 列含其他"分公司"结束（注意"小计"在 B 列非 A 列，勿用它做边界）。

### 2.2 总部履约跟踪表

**任务**：把底稿数据填到【总部履约跟踪】（全案履行记录，如 202608总部履约跟踪.xlsx）。

- **匹配键**：按「原告 + 案号数字」匹配（正则 `民(?:初|终)(\d+)号` 提取）。总部表案号格式较乱（全角括号/空格/缺括号），先规范化再比对。
- **核心逻辑**：总部表「未履行金额 P」列 ← 底稿同案「未支付金额」列合计（同一案件多行款项合并）。比对 P 与底稿合计，不一致即更新。
- **关键规则**：
  - **新增案件**：底稿有、总部表没有的先问用户。**注意：底稿中"公司"自己监控的案件不加进总部台账**（总部台账是"对局"的，公司自己监控——××建材/××项目因此被否）。案号 "/" 需向用户要案号。
  - **已支付完毕**：底稿未支付金额=0 且 支付流程节点='已支付'/执行情况='支付完毕' → 总部 P 归 0、O=M、S='是'、R='否'、U='已支付完毕'。T 列（履行完毕时间）底稿常无日期，留空待补。
  - **漏计利息/诉讼费**：总部 M 常只含本金（如×××、×××、×××6 漏利息/诉讼费），按底稿补进 M/P。但同一原告不同案件口径可能不同（×××含利息、8120不含），逐案核对。
  - **负数冲减**：底稿未支付金额为负（如××7351 万江一标 -4605.18 多付冲减）要计入合计，总部原值常未冲减。
  - **特殊案**：三菱30612 总部 U 写"我方上诉，未生效"，本金 2232520 已付（供应链已签发）、未付仅利息130000+诉讼费31114 → P=161114。
  - **新增行**：序号列 A 留空，B/C='公司'/'××分公司'，K='局'，L='资金支付类义务'，X/Y='否'，Z/AA='是'，AB 填支付方式（现金/供应链）。
  - **填后标黄**：所有填写单元格 PatternFill('FFFF00') 标黄。
- 参考脚本：`C:\Users\ACME\.workbuddy\tmp\write_hq.py`。写入前先备份原文件到 tmp。

### 2.3 对上级月度报送台账

**任务**：把当月/上月收案、和解、判决信息汇总到「对上级月度报送.xlsx」（被诉案件台账，每月报局）。

- **输入文件**（同目录）：
  | 文件 | 用途 |
  |---|---|
  | YYYYMM对上级月度报送.xlsx | 目标 |
  | YYYYMM分公司履约跟踪.xlsx | 待履行/未支付/支付方式（SSOT） |
  | YYYYMM总部履约跟踪.xlsx | 局口径应履行/已履行/未履行 → AY/BP/AM |
  | YYYYMM律师开庭台账.xlsx | 代理人、案件状态、标的、法院 |
  | YYYYMM律师结算【XX】.xlsx | 律师费/风险代理费/减损 → AN/BQ |
  | YYYYMM和解历史.xlsx | 已和解清单 → L="已和解" |
  | 公司项目编码.xlsx | 项目全称/600码/开工日期/分类（见 references/project-codes.md） |

- **责任单位筛选（最高优先级，2026-08 第五轮收紧）**：**只有被告含「××××工程局有限公司」的案件才录入**（AD 列子串匹配）。告公司/安装公司/其他单位的（如中科建筑告××××公司安装、石茂林告××××有限公司）一律不录。原「经办人=×××例外」**已取消**。注意 H 案件名称与 AD 列可能不一致（珠海嘉恒30653 AD 曾误填原告名，H 明确诉四局→以 H 为准修复 AD）。

- **案号规范**：全角圆括号（），半角数字，无空格无斜杠。立号→找对应民初号（生效文书/履约跟踪）。无民初号→按法院编号映射保留"(YYYY)粤xx民初"待补。

- **项目编码**：优先 600 开头（查 references/project-codes.md）；只有 12 开头的保留。实地项目（实地三四/木槿/小学/五期/四季水乡）都填 6000000155、名称"惠州实地东部现代城花园三、四期"（同一会计对象）。江门汽车城（武汉市政案）无立项→编码填 0。

- **AY 取大值**：参考分公司履约跟踪 + 总部履约跟踪，**取大值**。BP 按总部履约跟踪已履行金额。AM=AY-BP（保证检查公式通过）。一审中→AY=0, AM=AL；二审中→AY=0, AM=AL（看一审结果）或0；调解履行中→AY=调解金额, AM=未付；胜诉/撤诉→全0+BE=履行完毕日。

- **检查公式 BX**：`=IF(ROUND(AY-BP-AM,2)=0,"√","请检查")`。实操：openpyxl 直接写字符串值，不写公式。"请检查"主要是一审中/二审中案件（AY=0, AM=AL→-AL≠0 属合理）。

- **修改标黄**：所有改动单元格 `PatternFill('solid', fgColor='FFFFFF00')`。最终值与"原文档"一致的非新增行 → 取消标黄。

- **和解决定 L**：查 YYYYMM和解历史.xlsx，有则"已和解"，无则保留原值（无法协商一致/双方对付款方案未能达成一致）。

- **W 列（涉案项目性质）映射规则**（与 references/project-codes.md 的 cat 列对应）：
  - cat 前缀"工程项目/基础设施建设项目/…"→ **基础设施**（市政道路/公路/桥梁/隧道/水务/风电/污水处理/管廊等）
  - cat "房屋建设项目/工业加工厂房、工业制造厂房"→ **工业厂房**（明阳二三期、鼎湖科技园、鄱阳C、翠亨生物医药、OPPO数据中心、华为南方工厂、粤福电子、中山工业技术研究中心等）
  - cat "房屋建设项目/教育设施"→ **基础设施**（W 无"教育设施"类，归基础设施：紫茶中学/丰泰小学）
  - cat 其他"房屋建设项目"（住宅/保障房/写字楼/酒店/医疗等）→ **房建**
  - **特例（不受 cat 分类影响，用户确认）**：华大基因中心（6000000434/6000001428）→ 工业厂房；vivo深圳总部基坑（6000004428）→ 工业厂房
  - 编码表查不到的行（12 开头旧码/0）保持现状。
  - 多编码案件（\| 分隔）按主要争议项目定，多为房建（如××7351、××、方中环保）。

- **AD 列（被告/被申请人）规则**：被告、第三人单位全部塞进 AD 列，但**不写"第三人"字样**（如"…\n第三人广州市亲力劳务派遣有限公司"→"…\n广州市亲力劳务派遣有限公司"）。

- **状态判定速查**：
  - 未判决（一审中/二审中/仲裁中）→ AV='/'、AW='/'、AY=0、BK=0、AM=AL（或 0）；BX 显示"请检查"属正常
  - 调解履行中 → AY=调解金额、BP=已付、AM=未付、BX=√
  - 审结尚未履行完毕 → AY=判决金额、BP=已付、AM=未付、BX=√
  - 结案 → AY=0、AM=0、BE=执行完毕日期
  - 胜诉/撤诉 → AY=0、BP=0、AM=0、BE=撤诉日期
  - **履约跟踪有数额 = 已取得生效判决**：若底稿/总部里该案有具体债务数额而台账仍写一审中/二审中 → **先问用户**再定 AT。
  - **执行列逻辑**：BE（执行完毕时间）仅当 BA=是 或 BM=是 或 BN>0 时才能写；BN 有金额→BA=是+BM=是；撤网日≠履行完毕日。
  - 日期格式一律 `YYYY/MM/DD`（不要 YYYY-MM-DD）。

- **法院编号**：见 references/court-codes.md（罗湖已修正为粤0303）。

### 2.4 报财务（生效待履约跟踪金额）

## 三、交叉核对任务

### 3.1 履行情况 ↔ 付款明细表-待支付列表 核对

- **目的**：核对法律文书付款单是否已进入财务「待支付」登记。
- **匹配键**：底稿「支付单号」（JFK/YFK/CFK/TBZ/JFZ/FFK… 前缀）↔ 付款明细表-待支付列表各分公司分表的「司库一体化平台单据号」。用正则 `[A-Z]{3}\d{6,}` 抽取（单元格常含多单号/换行混排）。
- **结果解读**：
  - 匹配率通常很低（约 10%）——历史月度分表「未支付金额=0」已付清，本就不在待支付列表（正常）。
  - 真正关注 **未支付金额>0 但不在待支付列表** 的单子（疑似漏登缺口）。
  - 缺口里状态写「已办理供应链/已提单待支付/已支付部分」的，可能已在财务侧换号重提，需用「原告+金额」二次交叉确认。

### 3.2 供应链签发 ↔ 专项借款 交叉核对

- **两个表不同批次**：审核表（标题写当月，日期在前）记录已签发的供应链；专项借款 PDF（标题写次月，日期在后）记录新一批借款申请。
- **匹配键**：供应商 + 项目编号 + 金额（按供应商+编号聚合金额后比对）。
- **必须把上一批【借款申请】PDF 也拉进来一起看，否则会把「上月已签」误判为漏登**。
- **已知「不能 1:1 对应」的情形**：
  - ××建材：签了供应链（按多项目拆 12 笔），但专项借款里走「现金」不写「供应链」→ 供应链核对里完全找不到。
  - vivo基坑 / 三菱 30612号 / ×××6号 / ×× 16150号：上月已签供应链，下月未申请 → 已闭环，不是漏登。
  - ××× / ××万江一标：签发金额与申请金额拆分不同，需核实剩余部分。××万江一标签发 3 笔（23,927.75+999,132.56+994,527.38），下月只申请 1 笔 1,023,060.31，缺 994,527.38 那笔。
  - 宝茵翠亭（××）：同一项目两个编号（1220010778 vs 1220101616），合并看待。
- **PDF 为扫描件无文本层**，提取需 `fitz`（PyMuPDF）渲染图片 + Read 工具直读（OCR 备用 tesseract）。

## 四、通用规则

### 4.1 案号规范化

- 全角括号（）→ 半角 ()；去所有空格（含全角空格）；去斜杠。
- 提取核心键（用于跨表匹配）：`粤(\d+)` 法院代码 + `民(初|终|特|再|监|申|调)(?:\(调\))?(\d+)` 类型+序号；还有 `穗天综调(\d+)`、`行审(\d+)`、`仲案字(?:第)?(\d+)`。
