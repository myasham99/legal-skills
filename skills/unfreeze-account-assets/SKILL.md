# 解冻账户核对与盘点表校准（unfreeze-account-assets）

××××公司公司**财产保全解冻核对**专用技能：以财务实时台账（2.0版）为基准，核对/校准《被诉案件-上级法治考核指标盘点.xlsx》中 P/Q 列的状态，输出"P 列需改格子清单"并（经用户确认后）直接改表。

## 何时使用
- 用户给两份台账（盘点表 + 财务冻结台账），要求"核对 P/Q 是否一致""哪些格子要改""哪些还没解冻"。
- 用户提到"重复冻结""还有账户未解封""K列为0算解冻"等概念。
- 需要给盘点表 P 列批量填"是/否"、Q 列填解冻日期。

## 两份台账的字段映射

| 角色 | 文件 | 关键列 |
|---|---|---|
| 盘点表（要改的一方） | 被诉案件-上级法治考核指标盘点.xlsx | 数据行5~161(序号1~157，末行合计)。A序号 B执行案件号 C冻结额度(元) F申请人/原告 G责任单位 **H责任分公司** I是否已更正责任单位 O局2.0序号 **P=是否解冻(据财务冻结台账)** **Q=解冻时间** R案件状态 T进展 X备注(待反馈财务事项)；**整行删除线=已了结/剔除，P/Q 一律不管** |
| 财务冻结台账（财务基准） | 财务冻结台账.xlsx | 表头3~5行，数据从第9行起。A序号 D账号 E账户名 H冻结时间 **I执行案件号** J冻结额度(元) **K实际冻结金额(元)** **L=是否解冻(是/否)** M冻结法院 N原告 P案件责任二级单位(局属二级) Q民事案号 W实际解冻日期 X备注 |

## 核心判定口径（用户 2026-09-09 确认，勿改）

1. **账户是否已解冻** = `L列=='是'` **或** `K列(实际冻结金额)==0`（L=否 但 K=0 → 也算已解冻，账户无实际冻结款）。仅当 `L=否 且 K>0` 才是**真未解冻**。
2. **K 为空/'-' 且 L=否** → 存疑：不能直接判"未解冻"，提示用户人工确认（参考案例：87312 案 row423 K 空）。
3. **同一案件（重复冻结）**：同一执行案号（去掉"之X"子号，可再去尾部"号"）在 财务冻结台账有多个账户行 = 对多个账户重复冻结同一笔额度。**案件级状态 = 只要仍有任一账户真未解冻 → 案件未解冻**。
4. 盘点表 P 期望值：案件还有真未解冻账户 → `否`；全部账户解冻（L=是 或 K=0）→ `是`。
5. **用户行文约定**（盘点表填法）：
   - 同案多行（重复冻结）：只要还有未解冻账户，**保留其中 1 行 P=否 即可**，其余同案行可保持/填"是"——不必把同案每一行都改成否；
   - 行内"否"与实际未解冻账户可能错位（盘点表不一定有"之X"那行）→ 若发现"否"行对应账户其实 L=是，可提示"未解冻账户实为 之X（序号NN）"，是否补行由用户定；
   - **删除线行跳过**（已了结，不改 P/Q）；
   - **财务冻结台账查无案号的行**：无法判定，不自动改，列入"人工核实"（多为已全解冻被财务删行 / 非公司案件 / 土木投资等不在表内单位，可参考 X 备注）；
   - 日期取 财务冻结台账 W（实际解冻日期）；注意 W 可能是 **Excel 序列数**（如 46100=2026-03-19，openpyxl 读出 float 而非 datetime），必须转换后再比/填。
6. 输出形式（用户偏好）：核对结论用**横排 markdown 表格**；"P 需改清单"含 Excel 行号、案号、申请人、责任分公司、P现值→应改值、依据（2.0 行/序号/L/K）；**未经用户确认不要直接改盘点表**。

## 匹配与归一化技术要点

- 案号归一：全角括号→半角、去空格；去 `之.*$`（中文/数字子号都去，`\d+` 匹配不了"十四"）；再去尾部"号"做分组键 k3。两个账户行写法差异（如"7758号之一" vs "7758"）必须归一到同键，否则错判。
- 同一母案号多个账户行、金额相同 → 重复冻结；还需校验同法院同原告（M/N 列），不同原告不算同案。
- 盘点 B 列可能有多个案号（逗号/顿号分隔，如"5887号之十、(2023)…5887号之二十一"、"6713、6714号"）→ 逐段拆分判。
- 日期转换函数：datetime / Excel serial(int/float) / 文本(2026/4/27、2026-04-27、'2026/427') → YYYY-MM-DD。

## 改盘点表的无损方法（重要！文件内嵌 72+ 张证明材料图片）

⚠️ **禁止**用 openpyxl `load_workbook` + `save` 整表另存（会丢全部内嵌图片）。改 P/Q 值用**字符串级/zip 最小手术**：

1. 先 `cp` 备份原文件到临时目录；副本上实验、验证后再改原文件。
2. 直接改 `xl/worksheets/sheet1.xml` 与（如涉及新样式）`xl/styles.xml` 两个 zip 成员，其余条目原样写回。
3. **改文本值**：P/Q 多为共享字符串（`<c r="P35" s="24" t="s"><v>35</v></c>`，v=sharedStrings 索引）。先查 `xl/sharedStrings.xml` 中"是/否"的 idx（本例 idx35='是'、idx31='否'），再整串替换目标 `<c ...>` 片段的 `<v>idx</v>`。日期 Q 列通常无 t、v 为 Excel 序列整数 → 直接替换 `<v>` 数值或给空 `<c .../>` 补 `<v>序列</v>`（如 2026-01-14 = 46036）。
4. **改样式（标黄）**：styles.xml 的 cellXfs 末尾追加克隆 xf（改 `fillId=2`（FFFF00 黄色通常已存在于 fills）、`applyFill="1"`），并**同步 cellXfs count 属性 = cellXfs 内实际 `<xf` 元素数 + 新增数**（原 count attr 可能与实际不符——Excel 修复遗留；以 `<cellXfs ...>(.*?)</cellXfs>` 内实际 `<xf\b` 计数为准）；sheet1.xml 目标 `<c>` 加/改 `s` 属性。
5. 完成后校验：zipfile `testzip()==None`、openpyxl 能开、`_images` 数量不变、目标单元格值/底色正确。
6. 教训（2026-09-09）：曾用 ElementTree 重写整个 sheet1.xml/styles.xml → Excel 打不开（属性顺序/空白/命名空间被破坏）；必须字符串级最小改动。改值前先精确匹配整段 `<c>` 字符串（出现次数必须=1），不匹配即中止，避免误伤。
